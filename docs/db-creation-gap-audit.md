# DB 생성 누락 점검 기록

작성일: 2026-06-01

## 한 줄 결론

운영 DB에는 현재 필요한 표 34개가 모두 있고 사용자별 보안 잠금도 켜져 있지만, 새 DB를 처음부터 만들 때 쓰는 마이그레이션 파일에는 확장 기능 표 생성이 빠져 있었다.

## 확인 결과

- 코드 기준 표: 34개
- 기존 마이그레이션이 직접 생성하던 표: 17개
- 수동 스크립트에만 생성 코드가 있던 표: 7개
- 생성 파일이 누락되어 있던 표: 10개
- 운영 DB 실제 상태: 34개 표 모두 존재, 모든 사용자 소유 표에 RLS 활성화

RLS는 "사용자별 잠금"이다. 예를 들어 A 사용자가 B 사용자의 운세 기록을 DB에서 직접 읽지 못하게 막는 장치다.

## 보강한 파일

`supabase/migrations/0003a_create_extended_feature_tables.sql`

이 파일은 `0003_gacha_collection.sql` 다음, `0004_rls_missing_tables.sql` 전에 실행된다. 그래서 새 DB를 만들 때 0004 보안 정책이 "표가 없다"는 이유로 실패하지 않는다.

## 보강 대상

- 르노르망·룬 점술 결과 표
- 저장한 궁합 상대 표
- 출석·오늘의 질문·균열·감정 기록·캐릭터 친밀도 표
- 라이트 전용 일일 리포트 캐시 표
- 성격 심층 리포트 캐시 표
- 누락 enum 값: 별자리·띠 운세, 르노르망 펼침법, 룬 펼침법

## 운영 DB 적용 상태

아직 적용 전이다. 내용은 모두 `IF NOT EXISTS` 방식이라 기존 데이터 삭제나 덮어쓰기는 없지만, 실제 운영 DB를 바꾸는 작업이라 명확한 승인 후 적용해야 한다.

승인 문구:

```text
DB 보강 마이그레이션 운영 적용 승인
```

## 추가로 발견한 보안 정리

과거 수동 DB 생성 스크립트 5개에 DB 접속 주소와 비밀번호가 직접 들어 있었다. 파일에서는 제거했고, 이제 `.env.local`의 `DATABASE_URL`만 읽는다.

이미 Git 기록이나 외부에 노출되었을 가능성이 있으므로 Supabase DB 비밀번호는 출시 전 한 번 회전하는 것이 안전하다.
