# 데이터 청소 정책

작성일: 2026-06-01

## 목표

사용자에게 필요한 기억은 남기고, 임시 데이터와 만료된 데이터는 자동으로 줄인다. 결제·환불·분쟁 기록처럼 법적으로 보관해야 하는 데이터는 임의 삭제하지 않는다.

## 바로 지워도 되는 데이터

| 데이터 | 기준 | 이유 |
| --- | --- | --- |
| 공유 이미지 원본 | 24시간 후 삭제 | 카카오톡 등 공유 메시지는 외부 캐시가 남고, 원본 보관 필요가 낮음 |
| 만료된 결제 준비값 | 만료 후 24시간 뒤 삭제 | 결제창을 열기 전 임시 확인값이라 오래 둘 필요 없음 |
| 실패·해지된 푸시 알림 기기값 | 404/410 실패 또는 사용자가 알림 해제 시 삭제 | 더 이상 알림을 보낼 수 없는 기기 |
| 빈 대화방 | 메시지 0개이고 7일 경과 시 삭제 | 사용자가 볼 실제 내용이 없음 |
| 사용량 카운터 | 180일 후 삭제 | 무료 사용 횟수 계산용이라 장기 보관 가치가 낮음 |

## 바로 지우면 안 되는 데이터

| 데이터 | 보관 기준 | 이유 |
| --- | --- | --- |
| 결제·구독·환불·웹훅 기록 | 전자상거래법 기준 최대 5년 | 결제 증빙과 분쟁 대응 필요 |
| 소비자 문의·분쟁 처리 기록 | 최대 3년 | 법정 보관 대상 |
| 프로필·사주·채팅·운세·궁합 기록 | 회원 탈퇴 또는 사용자가 직접 삭제할 때까지 | 서비스의 핵심 개인화 기억 |
| 공유 운세 링크 | 우선 자동 삭제 보류 | 친구에게 보낸 링크가 갑자기 깨질 수 있음 |

## 실행 순서

1. 먼저 "몇 개를 지울 수 있는지"만 세는 점검 모드부터 만든다.
2. CEO 승인 후 실제 삭제 모드를 켠다.
3. 한 번에 대량 삭제하지 말고 1,000개 단위로 나눠 지운다.
4. 삭제 결과는 날짜·종류·개수만 기록하고, 개인정보 원문은 로그에 남기지 않는다.
5. 개인정보처리방침 문구와 실제 삭제 기준이 다르면, 정책 문구를 먼저 맞춘 뒤 자동 삭제를 켠다.

## 1차 자동 청소 후보

- `pending_billing_issues`: 만료 후 24시간 지난 행 삭제
- `usage_quotas`: 180일 지난 행 삭제
- `push_subscriptions`: 영구 실패 또는 해제된 endpoint 삭제
- `chat_sessions`: 메시지 없는 빈 세션 중 7일 지난 행 삭제
- `storage.share-images`: 기존 24시간 삭제 유지

## 보류할 것

- 오래된 채팅·운세·궁합 기록 일괄 삭제
- 결제 이력 축소
- 공유 운세 링크 자동 만료

이 셋은 사용자가 직접 체감하거나 법적 증빙과 이어질 수 있으므로 별도 화면 안내와 정책 반영 후 진행한다.
