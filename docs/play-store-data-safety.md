# Google Play 데이터 보안(Data Safety) 양식 답변 — 인생의 회전목마

> 콘솔 경로: **정책 및 프로그램 → 앱 콘텐츠 → 데이터 보안**
> 아래 답변을 그대로 양식에 옮기면 됩니다. 근거는 실제 DB 스키마(`src/db/schema/index.ts`)와 개인정보처리방침(`/privacy`) 기준.

---

## 1단계. 데이터 수집 및 보안 (개요 질문)

| 질문 | 답변 |
|---|---|
| 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** |
| 수집·공유하는 모든 사용자 데이터가 전송 중에 암호화되나요? | **예** (전 구간 HTTPS/TLS) |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **예** — 앱 내 **설정 → 계정 관리 → 계정 삭제**로 본인이 직접 전체 삭제 가능 + 이메일(diabloss9999@gmail.com) 요청 가능 |
| (계정 삭제 URL 요구 시) | 웹: `https://carouseloflife.com/settings` (계정 삭제 메뉴) — 또는 별도 삭제 안내 페이지 필요 시 생성 |

## 2단계. 데이터 유형별 선언

각 항목: **수집함 / 공유함 / 처리 후 즉시 삭제(ephemeral) / 필수·선택 / 목적**

### 개인 정보 (Personal info)
| 데이터 유형 | 수집 | 공유 | 목적 |
|---|---|---|---|
| 이름(닉네임) | ✅ | ❌ | 앱 기능, 계정 관리 |
| 이메일 주소 | ✅ | ❌ | 계정 관리, 본인 확인 |
| 사용자 ID (카카오/구글 OAuth 식별자) | ✅ | ❌ | 계정 관리, 인증 |
| 기타 정보 — **생년월일·태어난 시각·성별·출생지** | ✅ | ❌ | 앱 기능(사주·운세·궁합 계산) |

> ⚠️ 생년월일·성별은 "기타 개인정보(Other info)"로 선언. 사주 서비스의 **핵심 기능 입력값**이라 목적 = "앱 기능".

### 금융 정보 (Financial info)
| 데이터 유형 | 수집 | 공유 | 목적 |
|---|---|---|---|
| 구매 내역 | ✅ | ❌ | 앱 기능(구독·결제 관리) |
| 결제 정보(카드번호 등) | ❌ **수집 안 함** | — | 카드 정보는 PG(NHN KCP/PortOne)가 처리, 앱은 **마스킹된 끝 4자리 + 빌링키**만 보관 |

> 카드 전체번호를 저장하지 않으므로 "결제 정보(payment info)"는 **선택 안 함**. 구매 내역만 체크.

### 메시지 (Messages)
| 데이터 유형 | 수집 | 공유 | 목적 |
|---|---|---|---|
| 기타 인앱 메시지 (멤버와의 채팅 내용) | ✅ | ✅ (Anthropic, **본문만**) | 앱 기능(AI 풀이/대화), 개인화 |

> 채팅 본문은 풀이 생성을 위해 Anthropic API로 전송됨 → **"공유함"으로 선언**. 단 이름·이메일·계정ID 등 식별정보는 함께 전송하지 않음(방침에 명시).

### 사진 및 동영상 (Photos and videos)
| 데이터 유형 | 수집 | 공유 | 처리 후 즉시 삭제 | 목적 |
|---|---|---|---|---|
| 사진 (손금 풀이 시 손바닥 사진) | ✅ | ✅ (Anthropic Vision) | ✅ **ephemeral** | 앱 기능(손금 분석) |

> 손바닥 사진은 분석 API 호출 후 **메모리에서 즉시 폐기, DB/스토리지 영구 저장 안 함** → "처리 후 즉시 삭제(processed ephemerally)" 체크. 손금 기능을 쓰는 이용자만 해당이므로 **선택**.

### 앱 활동 (App activity)
| 데이터 유형 | 수집 | 공유 | 목적 |
|---|---|---|---|
| 앱 내 검색/사용 기록, 기타 사용자 생성 콘텐츠 (운세 기록, 감정 기록, 타로 질문, 출석·수집 카드 등) | ✅ | ❌ | 앱 기능, 개인화 |

### 앱 정보 및 성능 (App info and performance)
- **수집 안 함** (자체 크래시/진단 수집 SDK 없음 — Vercel/Supabase 인프라 로그만, 별도 분석 SDK 미사용)

### 기기 또는 기타 ID (Device or other IDs)
- **수집 안 함** (광고 ID·기기 식별자 미수집. 웹푸시 endpoint는 알림 발송용 토큰이며 광고/추적 목적 아님 → 해당 없음 처리)

### 위치 / 연락처 / 건강 / 통화기록 등
- **수집 안 함**

> ⚠️ **판단 필요 항목 — 감정 기록(mood)**: 하루 기분(great~hard) + 짧은 메모를 저장. Google "건강 및 피트니스(Health)" 범주로 볼 수도 있으나, 의료/피트니스 데이터가 아니라 **앱 내 자가 기록 콘텐츠**에 가까워 **"앱 활동 > 기타 사용자 생성 콘텐츠"로 선언 권장**. 보수적으로 가려면 Health로도 가능 — 심사 반려 시 재분류.

## 3단계. 데이터 보안 관행
- 전송 중 암호화: **예** (HTTPS)
- 데이터 삭제 요청 가능: **예** (앱 내 계정 삭제 + 이메일)
- 독립적 보안 검토(선택): 해당 없음

---

## ⚠️ 별도 중요 — "앱 액세스 권한(App access)" 선언
로그인이 **카카오/구글 OAuth 전용**(이메일/비번 제거됨)이라, Google 심사자가 앱 내부를 보려면 접근 수단을 줘야 함.
- 콘솔: 앱 콘텐츠 → **앱 액세스 권한** → "모든 기능에 로그인 필요" 선택 → **심사용 테스트 계정 제공**
- 권장: 심사자가 **구글 OAuth로 로그인**할 수 있는 전용 구글 계정(이메일+비밀번호)을 만들어 제공하거나, 카카오 테스트 계정 제공.
- 지침란에 "구글 로그인 버튼 → 제공한 계정으로 로그인 → /today 진입" 흐름 한국어+영어로 기재.
